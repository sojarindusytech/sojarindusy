# Database runbook: security fixes, coupons and order GST (2026-10-15 release)

Run every file in **Supabase Dashboard → SQL Editor**, one file per run, in this order.
Do it on a staging project first if you have one.

## Already applied (from main)

These came with the invoices / quotes / RFQ work and are already live. Nothing to do; the
files below assume they are there:

`20261010_invoices_and_sales_settings`, `20261011_purchase_order_numbering`,
`20261012_rfq_numbering`, `20261013_quotes`, `20261014_quote_status_history`.

## 0. Before anything

1. Take a backup: Dashboard → Database → Backups (or `pg_dump`).
2. Run `preflight/20261015_preflight_check.sql`. It is read-only.
   Download the result as CSV and share it with the developer.
3. Check **Admin → Settings → Sales**: the seller state, "GST billing" switch and default GST
   rate there now decide the GST charged at checkout (see "What changes for orders").

## 1. Before deploying the new app version

These only add things or close holes. The current app keeps working.

| Order | File | What it does |
| --- | --- | --- |
| 1 | `migrations/20261015_01_security_hardening.sql` | Stops anonymous edits to products, prices, categories and storage; closes the hand-made holes on profiles (self-promotion to admin) and RFQs; takes SKU prices and stock off the public API; hides stock logs from customers |
| 2 | `migrations/20261015_02_schema_catchup.sql` | Adds `rfqs` if missing, `orders.invoice_number`; collision-free order numbers; at most one open **automatic** PO per SKU (`purchase_orders.is_auto`); stock never below 0 |
| 3 | `migrations/20261015_03_coupons.sql` | Coupon tables; order columns for the discount, the GST snapshot (`tax_snapshot`) and retry-safe checkout |
| 4 | `migrations/20261015_04_order_and_coupon_functions.sql` | Locked database functions for orders (per-line discount and GST), stock and coupons |

A `WARNING` in the output is informational. It says which optional step was skipped and why.
Any `ERROR` means nothing in that file was applied: stop and share the message.

## What changes for orders

- **GST** at checkout now follows Sales Settings, exactly like invoices: each SKU's own GST
  rate (or the default), CGST + SGST for customers in the seller's state, IGST otherwise
  (from the state on the customer's profile), and none when GST billing is off. Before, every
  order was charged a flat 18%.
- **Coupon discounts** are spread over the order lines they apply to and taken off before GST.
- **Invoices**: when an order is marked Delivered, the real tax invoice is raised from the
  order (same lines, discounts and GST) and its number saved on the order. The made-up
  `INV-…` number is gone. The invoice total is the order total rounded to the rupee.
- Orders placed before this release are unchanged and keep their 18% figures.

## Rolling back

`rollbacks/20261015_rollback.sql` has three sections. Section A is only for redeploying the
old app. The security fixes and the new order columns are intentionally kept.

## Checks after step 5

- Place a test order with and without a coupon; check the order total and the stock change.
- With a customer in another state, checkout shows "GST (IGST)"; in the seller's state,
  "GST (CGST + SGST)". Give one SKU a 12% rate and check its GST.
- Mark the test order Delivered: an invoice appears under Invoices with the same discount,
  GST and total (rounded to the rupee), and the order shows its number.
- Cancel another test order; the stock comes back and the coupon use is released.
- In an incognito window, the storefront still shows products, and no prices.
- As an approved customer, prices show and Add to cart works.
- Race test on staging: create a coupon with **Total uses = 1**, apply it in two browsers
  (two customers) and press Place order in both at the same moment. Exactly one order
  gets the discount; the other sees "This coupon has reached its usage limit."
- Double-click Place order: only one order is created.
