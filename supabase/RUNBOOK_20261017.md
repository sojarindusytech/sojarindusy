# Runbook: stock ledger (reserve at order, deduct at shipment / invoice)

Migration: `supabase/migrations/20261017_stock_ledger.sql`. Run it **after** 20261015_01..05 and
20261010..14, and **before** deploying the app version that calls it (the new app expects
`reserved_quantity`, `post_invoice_stock`, etc.).

## What changes

| | Before | After |
|---|---|---|
| `product_variants.stock_quantity` | units available (already net of open orders) | **units on hand** in the warehouse |
| `product_variants.reserved_quantity` | n/a | units promised to open, not-yet-shipped orders |
| Available to sell | `stock_quantity` | `stock_quantity - reserved_quantity` |
| Place order | stock -= qty | reserved += qty (rest = backorder) |
| Ship (or deliver, if shipping was skipped) | nothing | on hand -= qty, reserved -= reservation; **refused** if not enough on hand |
| Invoice for an order | raised at Delivered | raised at **Shipped**; customer sees it at **Delivered** |
| Hand-made invoice | no stock effect | on hand -= qty (refused if available < qty); edit = difference; cancel = give back |
| Shipped order | could be set back / cancelled | can only become Delivered or Returned |

Order invoices never touch stock: the order owns it (`invoices.stock_owner = 'order'`), so shipping
cannot double-count.

## 1. Before running

1. Take a database backup / snapshot.
2. Optional dry run of the backfill numbers (read-only):

```sql
-- Units currently held by open (not yet shipped) orders, per SKU. After the migration these become
-- reserved_quantity AND are added back to stock_quantity.
SELECT pv.sku, sum(
         CASE WHEN i ->> 'reserved_quantity' ~ '^[0-9]+$' THEN (i ->> 'reserved_quantity')::int
              WHEN i ->> 'quantity' ~ '^[0-9]+(\.[0-9]+)?$' THEN round((i ->> 'quantity')::numeric)::int
              ELSE 0 END) AS will_become_reserved
  FROM public.orders o
  CROSS JOIN LATERAL jsonb_array_elements(CASE WHEN jsonb_typeof(o.items) = 'array' THEN o.items ELSE '[]'::jsonb END) i
  JOIN public.product_variants pv ON pv.id::text = i ->> 'id'
 WHERE o.status IN ('pending', 'confirmed', 'processing')
 GROUP BY pv.sku ORDER BY 1;
```

## 2. Run the migration, then deploy

The migration is idempotent (the backfill only runs the first time, when `reserved_quantity` does not
exist yet). Orders already shipped, delivered or returned are flagged as fulfilled and are never
deducted again; existing invoices become `legacy` and never move stock.

## 3. Checks after the migration

```sql
-- On hand always covers reservations (the table also enforces this).
SELECT sku, stock_quantity, reserved_quantity FROM public.product_variants
 WHERE stock_quantity < reserved_quantity;                       -- expect 0 rows

-- Reservations equal what open orders hold.
SELECT pv.sku, pv.reserved_quantity AS reserved, coalesce(o.qty, 0) AS held_by_open_orders
  FROM public.product_variants pv
  LEFT JOIN (
    SELECT (i ->> 'id')::uuid AS id, sum(CASE WHEN i ->> 'reserved_quantity' ~ '^[0-9]+$'
                                              THEN (i ->> 'reserved_quantity')::int ELSE 0 END) AS qty
      FROM public.orders o
      CROSS JOIN LATERAL jsonb_array_elements(CASE WHEN jsonb_typeof(o.items) = 'array' THEN o.items ELSE '[]'::jsonb END) i
     WHERE o.status IN ('pending', 'confirmed', 'processing')
       AND coalesce(i ->> 'id', '') ~* '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
     GROUP BY 1) o ON o.id = pv.id
 WHERE pv.reserved_quantity <> coalesce(o.qty, 0);               -- expect 0 rows (new orders only)

-- Shipped / delivered orders that still have no invoice (the app retries on the next save of the order).
SELECT order_number, status FROM public.orders o
 WHERE status IN ('shipped', 'delivered') AND invoice_number IS NULL AND stock_fulfilled_at IS NOT NULL;
```

## Behaviour to expect

- Shipping an order whose units are not on the shelf (backorder not yet received, or reserved for other
  orders) fails with "Cannot ship this order. Not enough stock for SKU ... Receive the purchase order first."
- Receiving a purchase order adds on hand; the waiting orders can then be shipped.
- Stock edits (manual adjust, bulk update, CSV) cannot set on hand below the reserved units.
- Sales Settings > "Reduce stock when an invoice is issued" turns the hand-made invoice behaviour off.

## Rolling back

`supabase/rollbacks/20261017_rollback.sql`, then re-run `20261015_04_order_and_coupon_functions.sql`
(restores the old order functions) and redeploy the previous app version. Issued invoices and their
stock log entries are kept.
